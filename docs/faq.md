# 常见问题

## 这是外挂吗？会被封号吗？

**不是外挂，但取决于你怎么用。**

代码做的事：读一张**你自己提供的图片文件** → 认出牌 → 算数学。
它没有屏幕抓取、没有游戏进程注入、没有内存读写、没有包分析、
没有热键监听、没有悬浮窗实时提示。

但要说清楚：**如果你把它的结果用在线上对局的实时决策里，
大多数平台的用户协议都禁止第三方辅助，那可能违规。**
这个仓库不提供、也刻意不实现任何让这件事变方便的功能
（比如实时读屏）。原因见 [DISCLAIMER.md](../DISCLAIMER.md)。

安全的用法：复盘、练习、研究、写文章、教概率论。

## 这算赌博工具吗？

不算。代码里没有任何货币、筹码、赔率、下注、资金管理相关的东西。

它算的是"这手牌的数学期望"——那是概率论作业。
算期望和赌博是两件不同的事，区别在于你怎么用它、以及你所在地区的法律。

如果你要拿它做赌博相关的事，请停止。

## 为什么没有实时/自动功能？

三条理由：

1. **法律风险**。实时读取其他程序画面并给出对战建议，在很多司法辖区
   是灰色到黑色地带。
2. **平台规则**。几乎所有在线麻将平台的 ToS 都明确禁止。
3. **项目定位**。这个仓库想回答的是"麻将里有多少是可以算的"，
   不是"怎么在对局里作弊"。

删掉实时功能之后，代码反而更简单了：少了一个截屏后端层、
一个后台线程循环、一个悬浮窗，以及它们的一堆测试。

## 向听数到底准不准？

准。验证方式不是"看起来对"，而是两条硬约束：

1. 与**不剪枝的完整搜索**在 4100 组随机手牌（13/14 张、1~3 副露）上逐一对齐
2. 与和牌判定自洽：`shanten == -1` ⟺ 手牌真能和；`shanten == 0` ⟺
   存在一张牌摸到就能和

顺带说：写这个的时候剪枝方向搞反过一次，3500 组里 99 次算错，
而且**全部是把好牌算差、一次也没反向**。细节在 [math.md](math.md)。

## 和牌概率是怎么算的？为什么不能连乘？

因为**向听会一级一级往下掉**。正确做法是马尔可夫链：状态 = 还差几级到听牌，
每巡用"当前级进张数 / 未见面牌数"做转移概率。

还有一个坑：分母必须是**未见面牌数**，不是剩余牌山张数。
用后者会让尾盘命中率虚高（一手烂牌能算出 76%，真实蒙特卡洛只有 6.7%）。

推导和验证方法在 [math.md](math.md#3-逐巡和牌概率为什么不能连乘)。

## 为什么按期望值排，而不是按进张数排？

因为只看进张会推荐错。典型例子：

| 打 | 向听 | 进张 | 和牌率 | 放铳率 | 期望值 |
|---|---|---|---|---|---|
| 东 | 1 | 15 | 44.8% | 13.7% | **19.88** |
| 3m | 1 | 25 | 55.9% | 28.4% | 17.59 |
| 5m | **0** | 7 | 58.8% | 40.0% | 12.00 |

打 5m 立刻听牌、和牌率最高，期望值却最低——因为它是危险牌，
而且只有 7 张待牌。

## 危险度模型为什么没有"现物绝对安全"？

因为**国标、四川、广东都没有振听规则**。日麻里自己打过的牌不能被荣和，
所以"现物"是 100% 安全的；中国麻将里打过的牌别人照样可以和。

唯一绝对安全的只有一条：**四张都在场上**，这张牌不可能在别人手里。

所以 `safety.DangerModel` 是重写的，不是从日麻搬来的。
它是个**模型**（牌种 × 剩余张数 × 巡目 × 筋折扣），参数全在代码里，可调。

## 参数在哪调？

| 想调什么 | 改哪里 |
|---|---|
| 危险度 | `safety.DangerModel` 的字段 |
| 对手听牌率 | `strategy.TENPAI_BASE / TENPAI_GROWTH / TENPAI_CAP` |
| 听牌后平均待牌数 | `strategy.ASSUMED_TENPAI_WAITS` |
| 未听牌时的打点估计 | `strategy.PROMISE_RULES` |
| 巡目价值衰减 | `probability.turn_value(decay=)` |
| 顺位期望的波动 | `ev.placement_probabilities(sigma=)` |
| 起和番 / 底分 / 付法 | 对应 `RuleSet` 的类属性 |

## 支持哪些规则？

内置四套：国标（81 番 + 8 番起和）、四川血战到底（108 张 + 定缺）、
长沙（将有 2·5·8）、广东推倒和（鸡胡也能和）。

加地方规则有两种方式：写个 `RuleSet` 子类，或者用 JSON 声明式规则
（见 README 的"加一套自己的规则"）。

## 截图识别准吗？

在**标定好的场景**下很准：合成图测试 25 张随机截图 100% 正确，
13 张留空、亮度偏移也能认对。

真实游戏截图取决于你的模板包质量。关键点：

- 模板要贴近实际牌面（不要带背景边框）
- 换游戏 / 换分辨率 / 换皮肤都要重新标定
- 认不准时它会明确报"这一格不太确定，最像 3m（0.41）"，**不会瞎猜**

为什么不用神经网络：模板匹配**可解释**（每格有分数、有次高候选），
而且不引入模型文件、不需要 GPU。

## 为什么内核零依赖？

为了可验证、可移植。CI 里有一条专门检查：导入内核后 `sys.modules` 里
不能出现 numpy / PIL / cv2。只有 `vision/` 需要 Pillow + numpy。

## 为什么纯 Python 这么慢还要用它？

因为要**可读**。这个仓库的首要目标是"能看懂为什么这么算"，
而不是"每秒算一万手"。

如果哪天真要快，路径是清楚的：把 `shanten.py` 换成查表/位运算实现，
接口不变，其它模块一行不改。现在没做，因为两三百毫秒在交互上够用。

## 我能拿它做什么？

- 复盘自己的牌谱，看看当时打哪张期望值最高
- 学概率论：超几何分布、马尔可夫链、期望值，全都有一个真实场景
- 写文章 / 做视频 / 讲"麻将里有多少是可以算的"
- 验证某个流传的"麻将口诀"到底对不对
- 给你的麻将程序当计算后端（HTTP API / `import mahjong_kernel`）

## 我能拿它做什么（不能）

- 在线对局的实时辅助
- 自动打牌 / 托管
- 任何赌博相关的用途
- 把它包装成一个"必胜软件"卖给别人
